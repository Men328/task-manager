# Project Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Thêm Project: mỗi task / schedule / event bắt buộc thuộc 1 project, email được tự detect vào project theo description, người dùng đổi được project và làm việc trong 1 project qua switcher trên TopBar.

**Architecture:** Service Go mới `service/project` (schema `project`, gRPC :9090 / HTTP :8090) theo đúng layout của `service/calendar`. Task / calendar / event thêm cột `project_id NOT NULL` (FK composite chéo schema) và gọi project gRPC để kiểm tra project trước khi ghi. Mail-provider đưa danh sách project vào prompt DeepSeek (luật keyword dự phòng) và đẩy item không khớp đủ vào backlog. Frontend thêm Redux slice `project`, switcher, trang `/projects`, ô chọn project trong các form.

**Tech Stack:** Go 1.25, gRPC + grpc-gateway, fx, pgx/v5, buf (`make gen`), PostgreSQL + golang-migrate, React + TS + Mantine + Redux Toolkit + i18next, Vite.

**Spec:** `docs/superpowers/specs/2026-10-28-project-design.md`

## Global Constraints

- Project là **bắt buộc** cho task / schedule / event (DB `NOT NULL`, API trả lỗi nếu thiếu).
- **Không xoá project**, không có `DeleteProject` RPC; chỉ archive / unarchive.
- Project mặc định: tên `Chung`, `is_default = true`, mỗi profile đúng 1; không archive được; không bao giờ là ứng viên detect.
- Project archived: không detect, không gán item mới / đổi item sang được; item cũ giữ nguyên.
- Detect: chỉ ứng viên **không archived, không mặc định**; `PROJECT_MATCH_THRESHOLD` env, mặc định `0.6`; không khớp đủ → backlog `reason = "no_project_matched"`, `category` = loại đã phân loại.
- Subtask luôn cùng project với task cha; đổi project task cha → cả cây con; không đổi riêng subtask.
- Backlog không có project; số liệu backlog trong report vẫn theo cả profile.
- Statuses / lifecycle không đổi (theo profile).
- Frontend luôn đứng trong đúng 1 project (không có "Tất cả project"); project hiện tại lưu `localStorage` key `tm.currentProjectId`, mọi truy cập bọc try/catch.
- Mọi chuỗi UI mới có cả `vi` và `en`. Mã lỗi mới khai trong `common/errorcode/error_codes.json`, sync FE bằng `make error-codes`.
- Comment / log trong Go viết tiếng Việt như code hiện có.

## Review Focus

1. **Seed project mặc định thất bại / profile cũ không có "Chung"** → người dùng vẫn phải có project để tạo task: `ListProjects` tự tạo "Chung" nếu thiếu (idempotent). Test ở Task 3.
2. **LLM trả `project_id` không có trong danh sách / project "Chung" / project archived** → coi như không khớp, vào backlog. Test ở Task 10.
3. **Project service down khi mail-provider xử lý email** → không mất email: coi như không có ứng viên, vào backlog, log lỗi. Test ở Task 10.
4. **`localStorage` lưu id project đã archive hoặc không còn trong danh sách** (hoặc storage throw) → về project mặc định, không màn hình trắng. Kiểm thủ công ở Task 11.
5. **Đổi task cha sang project khác / gắn subtask vào cha ở project khác** → cả cây cùng project, không bao giờ lệch. Test ở Task 8.
